# 经验沉淀指南

> “读书是学习，使用也是学习，而且是更重要的学习。”——《中国革命战争的战略问题》

经验沉淀是战后的结构化复盘，不是每次 `WARN` 的流水账。只记录已验证的事实、判断与结果；证据不足时保留不确定性。

## 何时记录

| 场景 | 类别 | 必要证据 |
|---|---|---|
| 已验证的改进或重构 | `patterns` | 可说明的因果证据 |
| 重复出现或复盘确认的失败 | `anti_patterns` | 触发条件、损害和已验证替代方案 |
| 架构或治理选择 | `decisions` | 背景、备选方案和理由 |

普通操作、没有新证据的结论或不可复查结果不记录。一次重构可以分别形成模式与决策两条记录，不要依赖默认类别猜测含义。

## 闭环

```bash
openarch docs record --category patterns "简述"
openarch docs check --changed <生成的文档路径>
```

先写完内容，再检查相似候选。相似候选只供报告；由 Agent 判断合并、交叉引用或保留分离，并写下决定。DocumentStore 的提交方式取决于当前项目或共享 scope，不能把示例仓库路径写成通用命令。

## 写作要求

交代背景、原始证据、原因分析、采取的行动、验证结果、适用条件和反例边界。三个月后的另一位 Agent 应能知道发生了什么、为何这样决定，以及何时不能复用这条经验。
