# 门禁裁决响应指南

> “世界上怕就怕‘认真’二字，共产党就最讲认真。”——《在全国宣传工作会议上的讲话》

在响应 `PASS`、`WARN` 或 `BLOCK` 前，先读取命令输出和当前项目策略。数据与直觉冲突时，修改判断，不修改事实。

## `UNCONFIGURED`

架构策略没有声明 `rules_warn`/`rules_block` 时，`PASS` 只是“没有已声明策略被触发”。若 baseline 当前且有 P95/Top-3，Agent 应运行 `openarch review`，发起一次探索性校准并请项目所有者选择最小 WARN、两条独立 WARN 或记录暂缓理由。不得复制别的项目阈值，也不得在首轮自动 BLOCK。

## `PASS`

`PASS` 只表示已声明策略未触发。它不证明项目健康，也不证明未配置的规则、未支持的 provider 或 `UNAVAILABLE` 范围已经被覆盖。

## `WARN`

1. 确认触发规则、文件、实测值和证据状态。
2. 区分门禁事实、增量诊断和仅供解释的信号；任何单一指标都不能单独等同于腐化。
3. 依据职责、依赖和本次目标，修复、接受风险，或提出可审计的策略调整。不得为了通过而降低阈值、改动分类或删除证据。

## `BLOCK`

Agent 不得绕过 `BLOCK`。修复实际违规；若项目所有者明确变更策略，先记录理由并完成配置审计。随后重新运行与改动相称的语言验证和 `openarch check --staged --report`，报告结果。
